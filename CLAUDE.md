# CDate: Chabad Calendar (notes for Claude)

This repository is a hosted web app: a Chabad/Jewish calendar that is installed on the owner's phone (Pixel 6 Pro, Android) from GitHub Pages and sends push reminders. The owner works **from a phone only** and is not a programmer. Explain things in plain words, one step at a time, and do the git work yourself.
- **Links (owner's standing rule): always send every link in a text box (a code block), on its own line, so it can be copied easily on the phone.**
- **Version number (owner's standing rule): end every update message with the app's shown version number ("Version X.Y.Z", from `ccVerStr()`), e.g. a last line `📱 Version 12.4.1`.**

- Live site: https://justaboredbocher.github.io/CDate/ (GitHub Pages, `main` branch, root folder). **Moved (v126, owner: nothing people see should show his name; things only found by digging — app id, push server address, notices' history — may stay):** the repo moves from `mosheliberman03-maker/CDate` to `justaboredbocher/CDate` (GitHub Transfer). Both apps' `server.url` = the new address (APK 9 / Keep in Touch rebuilt); `CC_GH` picks the GitHub owner for download links from `location.hostname` (old one while still served there); `ALLOW` in the worker has both origins. The OLD address is kept alive by a fork on the old account with Pages set to `main` /docs: `docs/` = a "new home" card (in the old apps: download the update, then sign in again — localStorage is per address, accounts come back from the server) or a redirect to the same path at the new address (browsers), plus a `sw.js` that clears the old service worker. The push server keeps its old address (not seen by users).
- Push server: https://cdate-push.mosheliberman03.workers.dev (Cloudflare Worker named `cdate-push`, source in `server/worker.js`)
- Owner's location default: Foshan, China (timezone Asia/Shanghai). Users: fewer than a few dozen people.

## Files
| File | What it is |
|---|---|
| `index.html` | The whole app in one file (HTML + CSS + JS, about 380 KB). Edit it directly. |
| `sw.js` | Service worker (registered for every user on load): shows push notifications, focuses the app on tap, and keeps one saved copy of the app (cache `cdate-app-v1`): opening answers instantly from it and fetches the newest copy in the background; if that changed, it messages the page (`cdate-update`) and a "Tap to update" button appears. Fonts, `assets/` and icons are served from cache `cdate-static-v1` (stale-while-revalidate: instant and offline, refreshed in the background; rename a file to force a change through at once). |
| `hayomyom-en.json` | English Hayom Yom (Chabad.org translation, used with permission; the owner holds the written permission), keyed `"<monthKey>-<day>"` like `Ki-19`, `AI-14`. Each entry `{h: original date heading, p: [paragraph HTML with only b/i/br], t: 1 if translated in the app}`. 12 entries (13 dates) were translated from the Hebrew/Yiddish because the collector picked up the original. Loaded by `hyFill()`; the service worker keeps a saved copy. |
| `tools/` | The phone-browser bookmark tools used to collect it (Chabad.org blocks server downloads, 403); `prefetch-shiurim.js` (nightly shiur texts); `worker.html` (copy page for the server code). |
| `sefaria/` | Shiur texts saved nightly by `.github/workflows/shiurim.yml` (about 03:15 China time; yesterday to 8 days ahead). Sefaria's Cloudflare protection blocks live requests from the app on the owner's phone and from Cloudflare Workers, but answers GitHub's servers. The script runs the app's own reader (`rdBuild`) headless and saves the trimmed Sefaria replies under the names `rdLocal()` looks for. Texts are kept (they repeat in later years); day schedules older than 3 days are deleted. |
| `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png` | Install metadata and icons: **since v55 the simplified curious character** (no eyebrows, head tilted, eyes looking up to the side, white halo) on a navy gradient; rendered from `CCH_SVG` in a headless browser (scratchpad `icon.js`). |
(The in-page favicon `<link rel="icon">` is a base64 64px copy of the same character icon (v55, owner: the character replaces the aleph everywhere). The native APK icon and splash come from `native/assets/icon.png` / `splash.png` (same character; splash = navy with him in the middle).)
| `server/worker.js` | Cloudflare Worker source. **Not served from here**: changes must be pasted into the Cloudflare dashboard by the owner (Workers & Pages, then cdate-push, then Edit code, then Deploy). Needs KV binding `KV` and cron `* * * * *`. |

**GitHub Pages publishing can get stuck** ("Deployment request failed … due to in progress deployment"), especially after several quick pushes. Fix: run the `unstick-pages.yml` workflow (cancels deployments GitHub still thinks are in progress, then requests a fresh build). Avoid many pushes to `main` in a row. `tools/worker.html` has a Copy button for pasting `server/worker.js` into Cloudflare from the phone.

Do not add files named `index (1).html` or similar: only `index.html` is served. GitHub Pages tells browsers to cache for about 10 minutes, but the service worker bypasses that. **Updates apply themselves (owner, v27):** when the service worker reports a new copy (`cdate-update` → `ccAutoUpd`), the page reloads on its own if you haven't touched it yet (within 25 s of opening or returning) or as soon as you leave the app (reload while hidden); otherwise the "Tap to update" bar shows. Such a reload sets `sessionStorage cc_quiet` → `window.CC_QUIET`, which skips the logo intro and the opening sun/moon animation. Returning to the app asks the service worker for the newest copy (`fetch(location.pathname)`). Never auto-reload while a sheet, the reader, the assistant or the tour is open (`auBusy`).

## Inside index.html (main pieces, by function name)
- **Two "todays" (owner, v26):** `t0` = the ENGLISH date (changes at midnight; it no longer jumps at sunset). After sunset `HSH`=1 and `hDay(dt)` (= the next day for today) gives the day whose Hebrew date applies: `info()` builds holidays/Yom Tov/Hebrew-date plans (`heb`, `hmonth`, `yomadpagra`) from `infoBase(hDay(dt))` and the header's Hebrew date from it, while the user's English-date plans (`once`, `greg`, `weekly`…) stay on `ds(dt)`. The planner's "today/tomorrow/Monday" are English dates (`new Date()`); a Hebrew date said in words maps to that Hebrew date. Shiurim + Hayom Yom + the Chitas streak/stats use `shDay(dt)`: **by default (owner, v47) the English date** (change at midnight); only when ⋯ → Advanced "Shiurim follow the English date" is switched OFF (`cc_sh_eng`='0' per profile; unset = on) do they use `hDay` (new day's shiurim from sunset); `dkey()` keys `DN` by that day. To-do lists (`groups`/`dynGroups`), "Shabbos" label and parsha use `hDay(sel)`. `skyTick` re-renders when sunset flips `HSH`.
- **Calendar core:** `hd()` Hebrew date, `t0` today (English date, see above), `sel` selected day, `LC` location `{n,la,lo,tz}`, `setLoc(n,la,lo,tz)`, `zAt()` zmanim, `render()`, `panel()`, `upd()`. Study tracking lives in `DN` (key `YYYY-MM-DD` → `{chumash,tehillim,tanya,rambam3|rambam1,hy}`); `tog(k)` toggles one.
- **Repeating plans on the calendar (v28, owner: "my chavrusas aren't showing"):** the day panel (`panel`, `groups`, the `.sm` tap) uses `info(sel)`, so every plan shows on any day it happens. Owner (Nov 2026) asked for chords for Jewish songs; instead of copying other sites' chord pages he chose **a chord finder + his own songbook**. Not part of the calendar (the calendar's `sw.js` passes `/songs/` through). Live at https://mosheliberman03-maker.github.io/CDate/songs/ once on `main`.
- `songs/index.html`, one file, no server, nothing leaves the phone. Choose a recording (audio/video file) or Record (MediaRecorder) → `convert()` → `decode()` (OfflineAudioContext at 11025 Hz, mono, max 15 min) → `listen()` runs `dspMain` in a Worker made from its own source.
- **`dspMain` / `analyze(x,sr)`:** (1) 4096-point FFT peaks → pitch (tuning offset from the peaks' circular mean), overtones removed lowest-note-first (`HO`/`HG`), → chroma + bass chroma; (2) beat: spectral-flux envelope (hop 128), autocorrelation tempo (prefers a faster count ≤176 that fits ≥80% as well; under 88 the beats are halved), Ellis-style dynamic-programming beats; no steady beat → half-second boxes (`bpm` 0); (3) chroma per beat; key (Krumhansl); (4) 24 major/minor templates + bass-root bonus + small in-key bonus, Viterbi with change penalty `PEN`; (5) a major chord becomes a 7 only when the flat seventh is clearly there. Returns `{dur,bpm,beats,ch,key,tune}`; a chord code = root·8 + kind (`QU`: '', m, 7, m7, maj7, dim, sus4, aug), −1 = none.
- **Songbook:** IndexedDB `songchords` (`songs` = the chart, `audio` = the recording's bytes by song id). Every converted song is saved at once. Song page: big current/next chord following the playback, speed 1×/¾/½, change key (`tr`, shown names only), 3/4 or 4/4 bars (`meter`, `off` = bar-line shift, guessed by `barOff`), "Fix chords" (tap a beat → picker; sets from that beat to the next change), name, words/notes, delete. Backup = JSON of the charts (not the recordings).
- Tests (scratchpad `songs/t.js`: synthetic songs with known chords, 8 styles, 99–100%; `songs/e2e.js`: the page in a phone-sized browser). **Never tested on real recordings in the workspace** — expect mistakes on busy/live recordings; tune `PEN`, `HG`, the bass bonus with real examples from the owner.
- **Many songs at once (owner):** the file box is `multiple`; 2+ files → `addMany()` saves each as a waiting song (`pend:1`, bytes in `audio`) and `runQ()` works through them one by one with a banner `#qB` ("3 of 100"); unreadable files are dropped and listed at the end. `runQ()` also runs on load, so closing the page mid-way loses nothing. A screen wake lock is held while it works. It never plays the songs (analysis takes seconds per song). A website cannot keep working once Android closes or freezes the page — true background work would need the Android app or a server.
- **Declined / not built:** Spotify or YouTube playlist links (ripping those streams breaks their terms, Spotify's are copy-protected, and a web page cannot fetch them anyway — told the owner to use files he has or Record). **Words by themselves (asked, not built):** recognising SUNG Hebrew is not reliable on a phone; a speech-to-text service (paid, recordings leave the phone, Hugging Face/Google are blocked in China) is the realistic route — waiting for the owner's decision.
- **Detail level (owner: "too accurate… correct but unnecessary chords", "changes in places that don't fit the strumming"):** `s.raw` = the beat-by-beat result, `s.ch` = what is shown/fixed, made by `simp(s)` from `s.lv`: 0 Simple (one chord a bar, two only for a clean half/half bar; 7ths dropped; a chord shorter than a bar between two of the same chord removed), 1 Normal (default: a chord may start only on beat 1 or, in 4/4, beat 3; majority of each half bar), 2 Every chord (raw). Control `#lvS`. Recomputed when the level, 3/4–4/4 or the bar lines change unless the song was fixed by hand (`s.ed`; changing the level then asks first). Songs saved before this get Normal on first open (`relv`).
